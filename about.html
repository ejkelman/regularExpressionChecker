About This Project

A Python tool that determines whether a regular expression over the alphabet {0, 1} is unambiguous.

Created by Elnatan Kelman

Inspiration

This project was inspired by the course material of MATH 249 — Introduction to Combinatorics (Advanced Level), taken at University of Waterloo and taught by Professor Stephen Melczer. See more of the course material at enumeration.ca.

Allowed Syntax

Only these characters are accepted:

0 1 * ( )

What Is Regex Ambiguity?

A regular expression is an expression of characters (here, '0' and '1') and rules to combine them. Using those rules, you can create various strings, which we collectively call a regular language.

An expression is unambiguous if, for each word in the language, there is exactly one way to use those rules to get to that word. It is ambiguous if some word can be derived in more than one way.

Note that ambiguity is a property of the expression, not the language.

0*0* — Ambiguous

The word 0 matches two ways: the first 0* takes the 0 and the second takes nothing, or vice versa.

(01)* — Unambiguous

Any word it accepts (ε, 01, 0101, …) can only be split into 01 blocks one way.

0*1* — Unambiguous

In any word like 0011, the boundary between 0s and 1s is forced.

0*0 — Unambiguous

The final 0 is mandatory, so the split of 000 is always "00 from the star, then 0".

(0*)* — Ambiguous

The inner 0* can match empty, so the outer star can repeat "nothing" infinitely many times.

How the Algorithm Works

The check runs in four steps:

  1. Parse

    The input is parsed by a recursive-descent parser into a tree with four node types: eps (empty word), sym (0 or 1), cat (concatenation), and star (repetition). Illegal characters or unbalanced parentheses raise a ValueError.

  2. Check for Empty-Word Ambiguity

    For every subexpression, count how many ways it can match the empty word (capped at 2). A star over anything nullable is immediately ambiguous.

  3. Build the Glushkov Automaton

    Each symbol occurrence is numbered (e.g., 0*0* becomes 0₁* 0₂*). The automaton has one state per position plus a start state. We compute:

    • nullable: can this part match empty?
    • first: which positions can start a match?
    • last: which positions can end a match?
    • follow: which positions can follow a given position?

    Transitions: start → each position in first, and position p → each in follow(p). Accepting states are positions in last (plus start if nullable).

  4. Search the Product Automaton

    Build the product of the automaton with itself. A product state is a pair (p, q) that moves on a symbol only if both components can. The regex is ambiguous iff there exists a pair (p, q) with p ≠ q that is:

    • reachable from (start, start)
    • co-reachable (both can reach accepting states)

    Both are found via BFS, which also reconstructs the ambiguous word.

Complexity

With n symbol occurrences, the product has up to n² states. The check runs in roughly O(n⁴).
